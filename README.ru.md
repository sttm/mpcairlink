# MPC AirLink — sttm

Нативный VST2-инструмент для Akai MPC Standalone: VBAN и AirPlay audio
на стереовыход Plugin track. MPC OS **3.10.1+**, Gen1 ARMv7 hard-float и
Gen2 AArch64. Аппаратный интерфейс с металлической панелью, физическими ручками и иконками, зелёный акцент **#8fe07a**.

| Поле | Значение |
| --- | --- |
| Имя в MPC / AirPlay | MPC AirLink |
| Производитель | sttm |
| ID | mpcairlink |
| VST UID | ArLk |
| Версия | 1.3.0 |
| Входы / выходы | 0 / 2 |
| VBAN | UDP 6980, ANY stream name |

## Установка

1. Распакуйте `dist/mpcairlink-1.3.0-mpc.zip` в корень SD/USB. Получится:
   `VST2 Plugins/sttm - VST - MPC AirLink/`.
2. На MPC OS 3.10.1+ включите Preferences → Enhancements (Beta) →
   Enable Enhancements и External Plugin Support. Подождите несколько секунд,
   затем перезапустите MPC.
3. Создайте Plugin track: External Plugins → sttm → MPC AirLink.
   Направьте выход дорожки на Main Out, снимите mute, установите громкость.
   MIDI-ноты и запуск секвенсора не нужны.
4. Оставьте носитель подключённым. Gen1/Gen2 бинарники уже лежат в одной
   папке; хост выбирает нужную архитектуру автоматически.

Старые выпуски до AirLink использовали другой UID. **AirLink — отдельный
плагин**, поэтому старые дорожки и сохранённые пресеты не переадресуются
автоматически. Замените инструмент вручную и сохраните копию проекта.
При обновлении не перезаписывайте `.so` загруженного плагина; закройте
проект/выключите MPC перед заменой папки на носителе.

## Управление

- **AirPlay**: источник по умолчанию для новых экземпляров, Mac и iPhone.
- **VBAN**: дополнительный источник для Windows/Android и других передатчиков; AirPlay helper и его объявление останавливаются.
- AUTO убран из интерфейса и логики плагина. Старое сохранённое значение AUTO трактуется как AirPlay. Предыдущие 14 ID/позиции сохранены; Source имеет индекс 14, Meter Refresh добавлен с индексом 15.
- **DIAG → VBAN Buffer**: 10–150 ms, по умолчанию 120 ms для новых экземпляров.
  AirPlay использует фиксированные 120 ms внутренней предбуферизации;
  настройка VBAN на него не влияет и не сокращает протокольную задержку AirPlay.
  Сохранённые проекты сохраняют своё прежнее значение VBAN Buffer.
- **Output Gain**: −24…+12 dB, по умолчанию 0 dB, со сглаживанием.
  При положительном gain возможен уровень выше 0 dBFS.
- **Q-Link 1**: только Output Gain на STREAM и DIAG; остальные Q-Link не назначены.
  Источник выбирается касанием AirPlay/VBAN, VBAN Buffer — на DIAG. Частота обновления уровней фиксирована на 24 Hz.
  Двойное касание регулятора открывает большой редактор.
- На STREAM: в AirPlay — имя приёмника MPC AirLink и подсказка выбора;
  в VBAN — крупный IP с портом UDP 6980 и имя потока. IP/порт скрыты в AirPlay.
  В обоих режимах — RECEIVING/WAITING, формат активного потока,
  потерянные VBAN-пакеты, стереометры с фиксированной частотой опроса 24 Hz.
- На DIAG: Lost, Drop, XRUN, служба/буфер, текущие имя/формат.

**Фильтра имён нет**: принимается поток с любым именем (ANY).
Имя потока произвольное: Stream1 — пример, а не обязательное условие.
Один активный источник — имя + IPv4 + source UDP port. Несколько потоков
не микшируются. Используйте один экземпляр AirLink на MPC.

## iPhone без стороннего приложения

1. iPhone и MPC должны быть в одной LAN/Wi-Fi, без client isolation.
2. AirPlay уже выбран по умолчанию.
3. iPhone: Пункт управления → аудиоплеер → AirPlay → **MPC AirLink**.
4. Включите музыку. На плагине появятся RECEIVING, AirPlay,
   `44.1 kHz / 16-bit Stereo` и уровни L/R.

Это AirPlay 1 / RAOP audio (ALAC, RSA/AES), не AirPlay 2, не видео,
не «Повтор экрана». Задержка обычно порядка 2 секунд, поэтому для игры
вживую предпочтительнее VBAN. Работает с приложениями, поддерживающими
AirPlay. Apple: https://support.apple.com/en-gb/105068

Обнаружение — multicast mDNS UDP 5353, сеанс — TCP 5000 и согласуемые
UDP-порты. Если служба не появилась, проверьте multicast и сеть, затем
переключите VBAN → AirPlay. Конфликт TCP 5000 требует остановки другого
AirPlay-приёмника. После изменения сетевого интерфейса может требоваться
перезапуск службы таким же переключением.


## VBAN Talkie (iPhone / Android)

В исходящем потоке TX задайте IP MPC, UDP **6980**, имя Stream1,
PCM signed 16-bit, **48000 Hz**, mono либо stereo. 44100 Hz тоже подходит.
Разрешите микрофон и доступ к локальной сети, включите Talk/постоянную TX.
Названия пунктов зависят от версии приложения. Talkie передаёт вход
микрофона; AirLink не добавляет захват системного звука телефона.

## Сборка и проверка

Docker Desktop на macOS, доступ к Docker Hub/Debian при первой сборке:

```sh
./build.sh
```

Контейнер linux/amd64, Debian bookworm, GNU C++17:
`arm-linux-gnueabihf-g++` для Gen1, `aarch64-linux-gnu-g++` для Gen2.
libstdc++/libgcc включены в VST статически; GLIBC не выше 2.36.
Зависимости AirPlay helper лежат отдельно в Content/AirPlay.

- Папка: `build/VST2 Plugins/sttm - VST - MPC AirLink/`.
- Установочный архив: `dist/mpcairlink-1.3.0-mpc.zip` и SHA256 рядом.
- UI-превью: `build/UI-preview.png`; это иллюстрация, не скриншот MPC.
- `./build.sh test`: ядро, SPSC, UDP, потери/reorder, host simulator.
- `./build.sh airplay-test`: реальные RTSP/RTP PCM и зашифрованный ALAC через VST2.
- `./build.sh sanitize`: ASan/UBSan, включая очередь VBAN и тест потерь.
- `./build.sh arm32` / `arm64`: только соответствующий бинарник.

SDK validator проверяет UID/имя/производителя, ELF, экспорт VSTPluginMain,
GLIBC, UI-ресурсы, индексы параметров и Q-Link. Предупреждение host simulator
о тишине без сетевого передатчика ожидаемо. Логи — `build/host-test.log`,
`build/airplay-test.log`, `build/airplay-alac-test.log`, `build/tac-vban-test.log`.
На MPC Key 61 / MPC OS 3.10.1 работа версии 1.0.0 подтверждена пользователем 2026-11-16.
Gen2 здесь проверяется компиляцией и анализом ELF; требуется отдельный
тест на реальном Gen2. После установки проверьте касания/Q-Link, проект
save/reload и длительное воспроизведение на MPC.

## Реализация и ограничения

UDP worker: nonblocking socket, poll, SO_REUSEADDR, getifaddrs. VBAN Audio:
все 21 частота таблицы, PCM16/24/float32, mono/stereo; NaN/Inf заглушаются.
Очередь 64 пакета ждёт reorder 2–12 ms; потерянный пакет сохраняет время
с затуханием. Для переменных размеров пакетов длина пропуска оценивается
по предыдущему. Нет FEC или восстановления исходного потерянного звука.

SPSC — 32768 stereo float frames, 32-bit lock-free atomics, блочная запись.
В processReplacing нет памяти, mutex, socket I/O или логов. Линейный SRC
сохраняет фазу между пакетами; FIFO feedback до ±0.3% согласует независимые
часы. Нет bandlimited anti-alias SRC; предпочтительны источники 44.1/48k.
Сетевые провалы дольше буфера всё ещё приводят к rebuffer.

AirPlay: отдельный bundled Shairport Sync 4.3.7 + TinySVCmDNS, без Avahi,
D-Bus, ALSA или установки системных служб. Helper копируется в приватный
/tmp каталог, зависимости загружаются только в дочерний процесс.
При выгрузке он завершается и временные файлы удаляются. TinySVCmDNS
помечен upstream как deprecated; обнаружение следует проверить в своей сети.

Диагностика: Lost — невосстановленные вовремя VBAN-пакеты; Drop — сумма
O (FIFO overflow) и T (отбрасывание большой очереди); XRUN — underrun.
Один XRUN после остановки передачи нормален. R — reset от хоста,
Q — заполнение FIFO в ms, H — объявленная частота хоста,
C — сглаженная частота потребления аудиоколбэком.

## Экономный UI и метаданные

Металлическая панель, свет, тени, кнопки, иконки и надписи заранее записаны в PNG.
Тестовая версия 1.3.0 использует послойные нативные ручки `RotatingImage`.
Насечка и белый указатель входят в одну вращающуюся картинку. Световая маска
и корпус неподвижны, центр имеет два кадра с небольшим изменением фактуры.
Рамки фокуса и оранжевая граница банка Q-Link убраны; управление Q-Link сохранено.
Поверх декоративных слоёв расположен прозрачный штатный FilmStrip-контрол:
он принимает вертикальный жест пальцем и меняет тот же параметр, что Q-Link.
Параметры 16/17 сохраняют прежние ID, диапазоны и значения по умолчанию.
16 неактивен после переноса Buffer в DIAG; 17 выбирает кадр центра громкости. Уведомления отправляет только поток UI при
изменении значения; постоянного таймера анимации нет. Проверка значений
совмещена с опросом уровней 24 Hz. Вращение выполняет UI
хоста напрямую по параметрам 2/3. Расход памяти PNG указан в VALIDATION.md;
это расчёт декодированных картинок, а не полный RSS хоста. Вращение и
альфа-смешивание могут потребовать больше CPU, чем готовый FilmStrip.
Быстрое вращение повторяющейся насечки может давать эффект медленного колеса.
Ориентация, касания и нагрузка нового скина требуют проверки на MPC.
Space Grotesk используется только при генерации картинок; его TTF не входит
в установочный ZIP. Динамические значения рисуются штатным шрифтом MPC.
Нет спектра, частиц, динамического размытия, web-интерфейса или QR-сервера.
Для каждого канала используются 23 готовых кадра: 0–22 полностью заполненных
блока. Область раскрытия больше не обрезает блок посередине. Индикаторы опрашиваются с фиксированной целевой частотой 24 Hz.
Переключатель частоты убран; прежний параметр 15 сохранён для загрузки проектов,
но его значение больше не меняет частоту опроса. Уровень имеет быстрый подъём и спад
по времени с постоянной 120 ms. Пики блоков аудио сохраняются до опроса UI.
Статусы проверяются отдельно с частотой до 10 Hz; касания/регуляторы
обрабатываются штатным UI сразу. Неизменившиеся кадры не отправляются хосту.
Это частота работы плагина, не управление глобальным FPS интерфейса MPC.
При спокойном VBAN-ожидании проверено отсутствие лишних UI-уведомлений.
AirPlay по умолчанию требует отдельного Shairport Sync helper — это сохранено
осознанно, как основной сценарий пользователя. В режиме VBAN helper выключен.

Это classic AirPlay/RAOP приёмник. Название песни и обложка в 1.3.0 не выводятся:
helper собран без CONFIG_METADATA, а динамическое обновление изображения
в штатной UI-системе MPC пока не подтверждено. STREAM показывает имя потока,
а не название песни. Метаданные и обложки требуют отдельного теста, не гарантии
нулевой дополнительной нагрузки. QR отложен в пользу минимальной нагрузки.

Проверены реальные UDP-потери/перестановки и PCM/ALAC AirPlay через loopback.
Дополнительно прошли 20 минут виртуального VBAN-воспроизведения с пакетами
256 frames, 48→44.1 kHz, дрейфом часов +/-1000 ppm и джиттером +/-1.5 ms:
ноль переполнений, обрезаний FIFO и underrun. Это симуляция, не 20-минутный
тест вашей Wi-Fi сети и не гарантия отсутствия потерь. Для прослушивания по
Wi-Fi начните с буфера 100–150 ms. VBAN использует UDP; потерянные исходные
аудиосэмплы буфер не восстанавливает.

1.0.0 проверен пользователем на Key 61 / OS 3.10.1; 1.1.1 пока проверен на
компьютере. Требуется проверка нового экрана и источников на MPC.
Предпросмотр design/airlink-v1.1.1/receiving.png — сгенерированная иллюстрация.
